Journal:

In phase 1, I created the basic foundation of my vault security system using JavaScript. I enabled "use strict"; at the top of my script, created an accessVault(key) function, and used an if/else statement to check whether the correct password was entered. I also tested the function with different keys to make sure it would grant access with the correct key and deny access with incorrect ones. This helped me understand how functions, conditions, and basic security checks work in JavaScript.

"use strict"; is considered a safety net for developers because it helps catch common coding mistakes and prevents certain bad coding practices. For example, it prevents me from accidentally creating variables without declaring them first. This makes my code cleaner, more reliable, and easier to debug. Basically, it helps me catch mistakes early before they turn into bigger problems.


In phase 2, I upgraded my vault security system by creating two custom error classes called InvalidKeyError and VaultLockedError. I updated the accessVault(key) function so that instead of just returning "Access Denied," it now throws specific errors depending on what went wrong. If the key is missing or corrupted, it throws an InvalidKeyError. If the key is provided but incorrect, it throws a VaultLockedError. If the correct key is entered, it grants access. I also used try/catch blocks to test the errors and display their messages in the console.

The difference between returning a value and throwing an error is that returning a value simply gives back a result, while throwing an error signals that something went wrong and interrupts the normal flow of the program until the error is handled. Developers might prefer custom error classes over a generic Error because they make it easier to identify exactly what went wrong. It also makes the code more organized and easier to troubleshoot. Overall, this phase helped me understand how JavaScript handles errors and how to make my vault security system more reliable.

In phase 3, I created a Master Access function called attemptEntry(key) using try, catch, and finally. This allows the vault to handle errors without crashing the whole program. I used catch to identify different errors and display the correct messages. I also used finally to make sure "Vault attempt completed." appears every time, whether the key is correct or incorrect.

The finally block runs every time, even if an error happens, while the catch block only runs when an error occurs. A real-world example would be an online banking app. If something goes wrong during a transaction, a finally block could make sure the connection is closed properly. This helps prevent problems and keeps the program running smoothly.
