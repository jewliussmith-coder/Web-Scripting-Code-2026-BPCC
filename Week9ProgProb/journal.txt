Phase 1:

In this phase, I created a feedback form and used JavaScript to intercept its submission and log the name, 
rating, and comments to the console. If I forget event.preventDefault(), 
the browser will submit the form normally, which can refresh the page and clear the entered data. 
Preventing the default behavior is necessary because there is no backend server to process the submission, 
so JavaScript needs to handle it on the current page.

Phase 2:

I used an array to collect all validation errors and display them together when the form is submitted. 
This helps users see everything they need to fix at once instead of submitting the form repeatedly.
 However, displaying multiple errors at once can feel overwhelming,
  especially if there are many errors, while showing one at a time may be simpler but takes longer to correct everything.


Phase 3:
In this phase, I added a success message for valid submissions and used localStorage to save the reviewer’s name so it remains available after refreshing the page. 
LocalStorage is often simpler than cookies because it is easy to access with JavaScript and does not automatically send data with every HTTP request. 
Cookies are more useful when a website needs to send information to a server, such as for session management and authentication.

Phase 4:

During testing, I checked empty submissions, incorrect ratings, missing keywords, and valid reviews to make sure the validation worked correctly.
I also refreshed the page to confirm that localStorage saved the reviewer’s name and displayed the welcome message. 
One improvement I noticed was that the form could be cleared or hidden after a successful submission.
